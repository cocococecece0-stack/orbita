# ORBITA GALAXY — аудит и план миграции

Дата: 2026-11-21. Ветка: `galaxy-main` (создана от `unity-main` @ `66738b3`).

## 1. Результаты аудита

### Что сохраняем без изменений

- `android/`, `ios/`, `dist/`, `node_modules/` — нативная база v3.8.
- `unity/Assets/Orbit/**` — предыдущая Unity-аркада (ядро `Orbit.Core`, uGUI `Orbit.Unity`, 35 WAV).
- `unity/Tests/Orbit.Core.Tests.csproj`, `unity/Tests/CoreTests.cs` — 23 зелёных теста старого ядра.
- `.github/workflows/build.yml` (теги `v*`), `.github/workflows/unity-build.yml` (теги `u*`), `.github/workflows/unity-core.yml`.
- Теги и релизы `v*`, включая `v4.0`, `v4.1`, и релиз `u4.0.0`.

### Что переиспользуем

- Инфраструктуру Unity 2022.3.74f1, uGUI и Newtonsoft-пакет (в старом ядре).
- `tools/generate_assets.py` как образец детерминированной генерации звука; для Galaxy создаётся отдельный генератор.
- Принципы версионирования JSON, бэкапов и миграций из `SaveStore.kt`/`SaveStore.swift` — но не сами данные v4 напрямую.
- Палитру и приёмы процедурной генерации спрайтов из `UiFactory.cs`.

### Что признано устаревшим для .io-арены

- Орбитальное движение, секторы, боссы старой арены, тетромино-режим Stack, сезоны/ежедневные миссии старой игры.
- Старые экраны и рендереры Kotlin/Swift, нативные PNG-ресурсы.
- Любая сетевая инфраструктура: её нет и не планируется.

### Критические риски, найденные аудитом

1. `OrbitBootstrap.Boot` помечен `RuntimeInitializeOnLoadMethod` и запускается в любой сборке. Решение: `GalaxyBootstrap` проверяет `Application.productName` и в Galaxy-сборке удаляет старые объекты через кадр; старый исходный файл не меняется.
2. Имена `Rng`, `ModeDef`, `AchievementDef` существуют и в `Orbit.Core`, и в `Orbit.Galaxy`. Смешивать `using` нельзя; новые файлы используют только `Orbit.Galaxy` или псевдонимы.
3. Оба ядра попадают в одну сборку без `.asmdef`. Добавляем изоляцию: `Orbit.Galaxy.Core`, `Orbit.Galaxy.Runtime`, `Orbit.Galaxy.Editor`.
4. Старый тестовый проект не должен подхватывать новые тесты. Новый проект лежит в отдельной папке `unity/Tests/Galaxy/`.
5. `Resources.Load("Audio/...")`_global_ — Galaxy-звук кладём в `Resources/GalaxyAudio/`.
6. Старый ключ сохранения `orbita.save.v4` не перезаписывается; Galaxy использует `orbita.galaxy.save.v5`.
7. Старый `BuildScript` создаёт только старую сцену; Galaxy получает собственный `GalaxyBuildScript` и сцену `Assets/OrbitGalaxy/Scenes/Arena.unity`.

## 2. Архитектура миграции

```
unity/Assets/Orbit/                  → ЗАМОРОЖЕНО (старая игра)
unity/Assets/OrbitGalaxy/
  Core/
    Types.cs, GameConfig.cs, ContentDatabase.cs   ← фундамент, общий для тестов
    World/        Arena, SpatialHash, WorldObject, WorldEventSystem
    Gameplay/     Ship, Combat, Growth, Absorption, Abilities, Evolutions, Bosses
    AI/           Perception, Utility AI, Navigation, BotBrain с LOD
    Match/        MatchSimulation, Leaderboard, MatchResult
    Progression/  AccountProfile, SaveManager, миграции, JSON-кодек
  Runtime/        GalaxyApp, Bootstrap, Input, Camera, Renderer, Ui/, Audio
  Editor/         ScriptableObject-конфиги, GalaxyBuildScript
  Resources/GalaxyAudio/              ← отдельные WAV
  Scenes/Arena.unity                  ← генерируется editor-скриптом
unity/Tests/Galaxy/                   ← отдельный xUnit-проект
.github/workflows/galaxy-core.yml     ← тесты ядра без лицензии Unity
.github/workflows/galaxy-build.yml    ← тег `g*`, бинарники при наличии секретов
```

Ядро не ссылается на UnityEngine и не использует Newtonsoft — это позволяет гонять его в net8.0 в CI без Unity.

## 3. Этапы реализации

| Этап | Содержание | Артефакт проверки |
| --- | --- | --- |
| 1 | Аудит, контракт, фундамент типов/контента, изоляция | `docs/GALAXY_MIGRATION.md`, `docs/GALAXY_CONTRACT.md`, коммит |
| 2 | Арена 2600 радиуса, камера, ввод, рендер, 28 участников | core-тесты генерации/пространственного индекса, Unity-рантайм |
| 3 | Рост, сбор ресурсов, поглощение по разнице масс | тесты роста/поглощения |
| 4 | Utility AI ботов, LOD, личности, конкуренция | тесты 20–35 участников и длинного матча |
| 5 | Боевая система, 7 способностей, 5 боссов | тесты урона/щита/способностей/боссов |
| 6 | 4 ветви эволюций × 3 уровня, визуальные формы | тесты предложений и применения эволюций |
| 7 | 7 живых событий, ресурсы, опасные зоны | тесты событий и арены |
| 8 | Рейтинг, TOP-10, итоги матча, стрики | тесты рейтинга и завершения |
| 9 | Прогрессия аккаунта, магазин, коллекции, задания | тесты сохранения/миграции |
| 10 | Полный UI, визуальная идентичность, звук | Unity-слои и сгенерированные WAV |
| 11 | URP 2D, object pooling, quality-настройки | editor-скрипты и manifest |
| 12 | CI, релиз `g*`, документация | зелёные workflow и release |

После каждого этапа — отдельный коммит и проверка через GitHub Actions. Локально Unity Editor, .NET SDK, Android SDK и Xcode недоступны; компиляция Unity-слоя проверяется только при наличии лицензии в CI, а чистое C#-ядро — в `galaxy-core.yml`.

## 4. Критерии готовности ядра

- Детерминированный матч с 20–35 участниками, при этом боты продолжают взаимодействовать вне зоны видимости игрока.
- Масса меняет скорость, урон, радиус сбора и правила поглощения; мелкий корабль может увернуться от крупного.
- Все 7 событий реально меняют арену и награды; не более одного активного события.
- Все 7 способности и 12 эволюций влияют на симуляцию, а не только на эффекты.
- Сохранение v5 восстанавливается после перезапуска, имеет бэкап и миграцию из старого формата.
- Тесты проходят для короткого матча, 35 участников и длинного прогона.

## 5. Что НЕ делает эта версия

- Не создаёт сервер, аккаунты, авторизацию, матчмейкинг, PvP по сети или ложные сетевые подключения.
- Не удаляет и не перезаписывает старые сохранения и исходники.
- Не обещает бинарные APK/IPA без секретов Unity в репозитории.

## 6. Текущий статус

Все этапы 1–12 реализованы и зафиксированы в `galaxy-main`: чистое ядро, арена и события,
рост/поглощение/бой, способности и эволюции, боссы, 20–34 бота с utility AI, режимы и итоги матча,
профиль v5 с миграциями и бэкапами, Unity-рантайм (камера, ввод, UI, рендер, звук), отдельные
сборки и тесты. Две независимые проверки в GitHub Actions зелёные: Galaxy core tests и legacy
core regression. Старые `v*`/`u*` workflow, теги и исходники не изменены.

Остаётся внешняя проверка: настоящая компиляция Unity-слоя и сборка APK/IPA выполняются только
в `galaxy-build.yml` при теге `g*` и наличии секретов Unity. Без секретов публикуется архив
исходников — это ожидаемое поведение, а не пропущенный этап.
